# AGENTS.md

This file provides guidance to AI coding agents (Claude Code, Codex, Cursor, Copilot, and others)
when working in this repository. It is loaded into agent context automatically — keep it concise.

## Overview

`rewtf-registry` is a single-file YAML registry of teams participating in the ReWTF program on
Flow. The only data artifact is `registry.yaml`; the Bun/TypeScript code in `scripts/` exists
solely to validate incoming PR additions against Flow-ecosystem criteria and GitHub API checks
(`scripts/bin/validate-registry.ts`, `scripts/bin/get-access-token.ts`). Contributors register by
appending an entry; a GitHub Actions workflow validates the PR and comments the result.

## Build and Test Commands

Runtime: Bun `>=1.0.0`, Node `>=20.0.0` (from `package.json` `engines`).

- `bun install` — install dependencies (uses `bun.lockb`).
- `bun run validate-registry` — runs `scripts/bin/validate-registry.ts`. Requires `GITHUB_TOKEN`
  env var. Writes result to `tmp/validation-result.json` and exits non-zero on failure.
- `bun run get-token` — runs `scripts/bin/get-access-token.ts`. Requires `APP_ID`,
  `APP_PRIVATE_KEY`, `INSTALLATION_ID` env vars. Writes token to `$GITHUB_OUTPUT` (CI only).

There is no `build`, `test`, `lint`, or `format` script defined in `package.json`. Biome
(`@biomejs/biome`) is listed in `devDependencies` but has no configured script and no
`biome.json` at the repo root.

## Architecture

```
registry.yaml               # The source of truth: flat YAML list of team entries
package.json                # Bun scripts + deps (@octokit/rest, @octokit/auth-app, js-yaml)
bunfig.toml                 # Bun config; registers `.cdc` files as text loader
tsconfig.json               # Strict TS, ES2020 target, bundler resolution, bun-types
scripts/
  bin/
    validate-registry.ts    # Main validator class `RegistryValidator`
    get-access-token.ts     # GitHub App JWT -> installation token (CI only)
    README.md               # Script-level usage docs
  src/types.ts              # `ValidationResult { isValid, errors[] }`
  tsconfig.json             # Extends root tsconfig
.github/workflows/
  validate-registry.yml     # PR workflow: validates registry.yaml, comments PR
```

Entry schema (enforced in `validate-registry.ts`):

- `name` (string, required)
- `github` (string[], required, non-empty) — validated via `octokit.users.getByUsername`
- `repos` (string[], required, non-empty) — validated via `octokit.repos.get` + Flow-ecosystem check
- `wallets` (optional): `evm` must match `^0x[0-9a-fA-F]{40}$`; `flow` must match `^0x[0-9a-fA-F]{16}$`
- `x` (string[], optional) — social handles

## Conventions and Gotchas

- **The validator only checks the LAST entry** in `registry.yaml`
  (`validate-registry.ts`: `entries[entries.length - 1]`). Reordering entries or adding multiple
  entries in one PR means earlier additions are not validated by CI. Always append new entries
  at the end.
- **Source of truth for Flow-ecosystem rules is the validator, not the README.** README.md lists
  `@onflow/react-sdk` as an accepted dependency, but `validate-registry.ts` (lines ~174–178)
  only accepts `@onflow/fcl` or `@onflow/kit` in `dependencies`/`devDependencies`. If a repo
  declares only `@onflow/react-sdk`, validation will fail unless another criterion passes.
- **Accepted Flow-ecosystem signals** (any one satisfies the check):
  README.md contains `on flow` or `flow blockchain` (case-insensitive); `package.json` depends
  on `@onflow/fcl` or `@onflow/kit`; `go.mod` references `github.com/onflow/flow-go-sdk` or
  `github.com/onflow/flow-go`; a Hardhat config contains `evm.nodes.onflow.org`. Foundry/Truffle
  configs are detected but their contents are not inspected.
- **Workflow trigger is `pull_request_target`** scoped to `paths: [registry.yaml]` on `main`
  (`.github/workflows/validate-registry.yml`). Changes to other files will not trigger CI.
- **`tmp/` is gitignored** (`.gitignore`: `tmp/*`) but `validate-registry.ts` calls
  `mkdirSync("tmp", { recursive: true })` and writes `tmp/validation-result.json`. Do not
  commit `tmp/`.
- **Wallet length rules are strict:** EVM = 42 chars total, Flow = 18 chars total. Many
  existing entries use left-padded Flow-EVM-style addresses like
  `0x000000000000000000000002...` — this is valid (still 42 chars).
- **`bunfig.toml` registers `.cdc` as a text loader.** No `.cdc` files exist in the repo today;
  this is forward-compatible config only.
- **Biome is installed but unconfigured.** Do not assume `biome check` is part of the workflow;
  there is no `biome.json` and no lint step in CI.

## Files Not to Modify

- `bun.lockb` — Bun's binary lockfile; regenerated by `bun install`.
- `registry.yaml` entries belonging to other teams — only append your own entry.
